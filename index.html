⚖️ Git vs. GitHub

Entenda de uma vez a diferença entre os dois.

● Git (O Motor)

É o programa instalado no seu computador. Funciona como uma "máquina do tempo" que grava e gerencia todo o histórico de alterações dos arquivos.

Funciona offline no seu PC

● GitHub (A Nuvem)

É o site/plataforma onde você hospeda seus repositórios Git na nuvem, compartilha seu trabalho e colabora com outras pessoas.

Hospedagem + Rede Social Dev

🧱 Os 4 Conceitos Fundamentais

O vocabulário básico que você vai usar todos os dias.

📁 Repositório

A "pasta" do seu projeto na nuvem onde ficam os códigos, imagens e histórico.

💾 Commit

Um "ponto de restauração" salvo com uma mensagem explicando o que você fez.

🌿 Branch

Uma ramificação para testar ideias e novas telas sem estragar o código principal.

🔀 Pull Request

O pedido para juntar sua branch de volta ao projeto após revisão da equipe.

🔄 O Ciclo de Trabalho (Workflow)

O caminho que qualquer alteração faz até chegar ao GitHub:

1. Modificar Edite no VS Code
➔
2. Selecionar git add .
➔
3. Salvar Foto git commit -m "..."
➔
4. Enviar git push
# Exemplo real:
git add index.html
git commit -m "Adiciona botão de login"
git push origin main

✨ Criando seu 1º Repositório

Passo a passo no site do GitHub (Interface Web):

1
Clique no botão verde "New"

Fica no menu superior direito do site.

2
Escolha um Nome Claro

Ex: meu-site-pessoal ou sistema-vendas (evite espaços e acentos).

3
Marque: "Add a README file"

O README é o cartão de visitas que explica o que é o projeto.

🌿 Trabalho em Equipe Sem Conflito

Como várias pessoas mexem no mesmo código sem apagar o trabalho das outras:

🔀 Branch Paralela

Nunca mexa direto na versão principal (main).

Crie uma ramificação tipo nova-tela-cadastro. Se errar, o site original continua no ar intacto!

🔍 Code Review (PR)

Terminou a sua tarefa? Abra um Pull Request.

Seus colegas de time olham as mudanças, deixam comentários de melhoria e aprovam a junção (Merge).

🛡️ 3 Regras de Ouro

O que você nunca deve esquecer:

1. NUNCA suba senhas

Senhas, chaves de API e arquivos de ambiente (.env) nunca devem ir pro GitHub. Use o arquivo .gitignore para bloqueá-los.

2. Mensagens com sentido

Evite commits como "ajustes" ou "corrigindo erro".
Prefira: "corrige alinhamento do banner mobile".

3. O README é a sua vitrine

Se ninguém entender o que seu projeto faz em 10 segundos, ninguém vai usar. Coloque uma foto, o objetivo e como rodar o projeto.

🎯 Desafio Prático (Mão na Massa!)

Exercício de 5 minutos para fixar agora:

  1. Acesse github.com e faça login.
  2. Crie um repositório chamado primeiro-passo (com README marcado).
  3. Clique no ícone de lápis ✏️ no próprio navegador para editar o README.
  4. Escreva seu nome, cargo e objetivo profissional.
  5. Clique no botão verde "Commit changes"! 🚀
🎉 Parabéns! Você acabou de fazer o seu primeiro commit!
